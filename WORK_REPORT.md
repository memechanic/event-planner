# Отчет по проделанной работе

## Кратко
В проекте доработаны backend и frontend части для:
- интерактивного календаря на главной странице;
- авторизации/регистрации пользователя;
- отображения списка событий пользователя;
- удаления событий пользователя;
- улучшения обработки ошибок и UX в форме входа.

---

## Что было добавлено

### 1) Новый функционал календаря на главной странице
**Файл:** `frontend/src/views/HomeView.vue`

Добавлено:
- интерактивный календарь с навигацией по месяцам;
- выбор даты и отображение событий выбранного дня;
- подсветка текущего и выбранного дня;
- индикаторы дней, в которые есть события;
- кнопка перехода к текущей дате (`Сегодня`);
- загрузка событий пользователя с backend и преобразование в формат календаря;
- блок `Мои события` со списком событий текущего пользователя;
- удаление события из списка (с подтверждением);
- состояния загрузки/ошибок для блока событий.

### 2) Эндпоинты для событий (список и удаление)
**Файлы:** `backend/events/views.py`, `backend/events/urls.py`, `backend/events/serializers.py`

Добавлено:
- `EventListSerializer` для выдачи списка событий;
- `EventListView` на базе `generics.ListAPIView`;
- `EventDeleteView` на базе `generics.DestroyAPIView`;
- маршруты:
  - `GET /api/events/list/`
  - `DELETE /api/events/<uuid:id>/delete/`

### 3) Разделение регистрации и входа
**Файлы:** `backend/events/serializers.py`, `backend/events/views.py`, `backend/events/urls.py`, `frontend/src/stores/auth.js`, `frontend/src/views/LoginView.vue`

Добавлено:
- отдельные backend-сериализаторы:
  - `EventUserRegisterSerializer`
  - `EventUserLoginSerializer`
- отдельные backend-view:
  - `EventUserRegisterView` (`POST /api/auth/register/`)
  - `EventUserLoginView` (`POST /api/auth/login/`)
- на frontend:
  - отдельные методы store: `register()` и `login()`;
  - в форме входа/регистрации две отдельные кнопки:
    - `Войти`
    - `Зарегистрироваться`.

## Что было изменено

### Backend

1. **Авторизация пользователей**
   - Ранее был объединенный сценарий `get_or_create`.
   - Изменено на отдельные сценарии:
     - регистрация (создание нового пользователя);
     - вход (поиск существующего пользователя и проверка имени/email).

2. **Валидация пользователей**
   - Добавлены явные проверки:
     - при регистрации: уникальность `username` и `email`;
     - при входе: существование пользователя по `email` и соответствие `username`.

3. **События**
   - Добавлены отдельные API для списка и удаления событий.

### Frontend

1. **`auth` store**
   - Рефакторинг методов авторизации:
     - выделены общие функции подготовки данных и разбора ошибок;
     - добавлены отдельные методы `login` и `register`.

2. **Форма входа (`LoginView`)**
   - Изменен UI:
     - отдельные кнопки входа и регистрации;
     - разные состояния загрузки для каждого действия;
     - показ понятной ошибки из backend в интерфейсе.

3. **Главная страница (`HomeView`)**
   - Календарь связан с реальными данными пользователя;
   - Добавлен список пользовательских событий;
   - Добавлена возможность удаления события пользователя;
   - Добавлена кнопка перехода к текущей дате.

## Какими способами реализовано

1. **Backend (Django + DRF)**
   - Использованы базовые классы `rest_framework.generics`:
     - `CreateAPIView`
     - `ListAPIView`
     - `DestroyAPIView`
     - `GenericAPIView` (для логики входа с ручным `post`).
   - Валидация реализована в DRF-сериализаторах (`validate`).

2. **Frontend (Vue 3 + Pinia + Axios)**
   - API-запросы через `axios`-клиент в `frontend/src/api/index.js`;
   - Логика авторизации централизована в Pinia store;
   - UI-контроль состояния через `ref/computed`:
     - loading/error состояния;
     - реактивное обновление списка и календаря после удаления.

3. **Интеграция frontend/backend**
   - Использованы эндпоинты:
     - `POST /api/auth/register/`
     - `POST /api/auth/login/`
     - `GET /api/users/<user_id>/events/`
     - `DELETE /api/events/<event_id>/delete/`
   - Данные событий преобразуются под формат календаря на frontend.
